# Saved Reports — design spec

**Date:** 2026-09-02 · **Module:** M10 · **Status:** approved, not started
**Supersedes:** the live-table Reports screen shipped 2026-09-02 (same day).

---

## 1. The change in one sentence

A report stops being *a table you look at* and becomes *a record you generate,
which is saved, listed, and downloadable again later*.

## 2. Why

The live table answers "what is true right now" and then forgets. Three things
the association actually needs, it cannot do:

1. **Prove what a file contained.** A spreadsheet mailed to the board six weeks
   ago is only trustworthy if it says which filters produced it.
2. **Repeat a run.** Monthly reporting means re-picking every filter by hand.
3. **Survive a rename.** A report filtered by "Gold" must still say *Gold* after
   the category is renamed to "Premium".

Modelled on the Dribee reports module (`Distrix_Project/dribee-backend`,
`dribee-admin`), studied 2026-09-02. What is adopted and what is deliberately
not is recorded in §7.

## 3. The four reports

Unchanged from what is already built and verified. Only *when* they run changes:
once, at generate time, instead of on every page load.

| Report | A row is | Filters |
|---|---|---|
| Members | one company | status · category · city · state · **member** · search |
| Revenue | one **month** | date range · invoice type · **member** |
| Renewals Due | one membership term | expiry range · cover status · **member** |
| Event Attendance | one event | event date range · **event** · search |

Bold filters are new. All multi-select, all optional; empty means "no opinion".

## 4. Flow

```
Report cards          Members · Revenue · Renewals Due · Event Attendance
      ↓ pick one
Generate drawer       name (auto-suggested) · date range · filters ·
                      [ ] include detailed breakdown
      ↓ Generate
Server                counts rows → refuses over 1,048,576 → runs the query →
                      stores the result + the filters → status 'ready'
      ↓
Reports list          name · type · row count · filters · details · by · when
      ↓
Row actions           View summary · Download Excel · Run again
```

## 5. Decisions taken

| Question | Decision | Reason |
|---|---|---|
| Background generation | **Not now.** Inline only | 9 members today; the cron runner already exists, so switching it on later is half a day. The over-a-million-row refusal ships now regardless. |
| Whose reports are visible | **Everyone's**, with a Generated By filter | An association office is a shared workspace. `report.view` already gates the data — anyone who can see the list could run the report themselves, so hiding results protects nothing. |
| Retention | **One year**, then pruned by a job | The cycle is annual: at the 2027 AGM you want the 2026 equivalent to compare. Detail rows in JSONB are the only thing that grows. |
| Generate permission | New **`report.create`** | Seed data, one line. Granted to the same three roles holding `report.view`, so nothing changes today — but the split exists the day a clerk should read without running heavy queries. |
| Member filter scope | Members, Renewals, Revenue. **Not** Events | Events takes an event filter instead. |
| Member Statement report | **Deferred**, own report type later | One member's full history is a different shape and would delay the rest. |

## 6. Data model

```
GeneratedReports
  id              bigserial
  report_type     varchar(40)  CHECK IN (members, revenue, renewals, events)
  report_name     varchar(200)
  from_date       date NULL
  to_date         date NULL
  filters         jsonb NOT NULL DEFAULT '{}'
  include_details boolean NOT NULL DEFAULT false
  report_data     jsonb NOT NULL DEFAULT '{}'
  status          varchar(20) CHECK IN (queued, running, ready, failed)
  row_count       bigint NOT NULL DEFAULT 0
  error_message   text NULL
  generated_by    bigint → AdminUsers(id) ON DELETE RESTRICT
  createdAt       timestamptz
```

`queued` / `running` / `failed` are in the CHECK from day one even though
nothing writes them yet: adding a value to a CHECK later is a migration, and the
background path is a decided future.

**`filters` stores `{id, name}` pairs, never bare ids.** A report is a
historical record; an id-only filter becomes unreadable the moment a category or
a company is renamed, and its saved numbers stop being explainable.

**No `file_key` column.** With inline-only generation there is no stored file —
the export is rebuilt from `report_data` on every download. The column arrives
with the background path.

## 7. Excel

**Sheet "Summary"** — always.

```
ILGDA — Members — Active · Gold
Generated: 2 Sep 2026, 3:14 pm · By: Meena Shah

Report Type      Members
Date Range       N/A
Filters Applied  Status: Active
                 Category: Gold

Total Members    238
```

**Sheet "Detail"** — only when `include_details` was ticked. The report's rows,
headed by the column registry's own headers.

**Filters are stated before any figure.** A filtered number read as an
association-wide total is the failure this design exists to prevent.

### Adopted from Dribee

- Summary + Detail sheet split
- Filters printed before the figures
- Detail columns stay **real numbers** — a column of text cannot be totalled
- Never set a fill on a `Row`: Excel paints a row-level style across all 16,384
  columns, so a five-column report shows a page-wide band

### Deliberately not adopted

- **Cr / L abbreviation.** Dribee's scale is crores; ours is ₹73,800.
  Abbreviating turns a number into text for no benefit.
- **A `COLUMN_LABELS` dictionary.** Dribee needs one because their collectors
  return raw database column names. Our column registry already carries the
  human header, so a new column cannot be forgotten in a second list.
- **Module gating of report cards.** No tenants, no modules.
- **Finance-style statements.** No report here has five variants.

## 8. Known gap in the source design

Dribee's list does **not** poll. A row reading "Generating…" stays that way
until the page is reloaded. Not an issue while generation is inline; it becomes
one the day the background path ships, and the fix belongs with it.

## 9. Open ambiguities

None blocking. Recorded for the approval gate:

- Whether a **duplicate** report — same type, same filters, minutes apart —
  should warn. "Run again" makes duplicates easy; Dribee's own list shows three
  identical rows. Left un-warned for now.
- Whether the one-year retention should be a **system setting** rather than a
  constant. Left a constant until someone asks.
